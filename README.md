## 业务流转

事项分四个状态：**待安排 → 等上门 → 处理中 → 已完成**。

1. 新增事项默认进入「待安排」。
2. 租客确认上门**日期 + 时段**（上午/下午/晚上）后，系统生成一个**六位数字临时上门码**，事项进入「等上门」。
3. **改约**：旧码立即作废并存档，生成新码；事项仍在「等上门」。
4. **取消**：旧码立即作废并存档，事项回到「待安排」。
5. 师傅到场在该事项上输入当前预约的码登记，核验通过才进入「处理中」：
   - 输错码、拿了别的事项的码 → 提示码不正确，**状态不变**；
   - 未到预约时段 / 时段已过（结束后 30 分钟宽限）→ 拒绝登记，**状态不变**。
6. 处理中可标记「完工」。
7. **费用合计只统计处理中与已完成的单**；待安排、等上门不计。

## 模块划分（分开维护）

| 文件 | 职责 |
| --- | --- |
| `src/lib/accessCode.js` | **码规则**：六位码生成、时段窗口、核验、作废。纯逻辑，不依赖 DOM/存储。 |
| `src/lib/workflow.js` | **事项流转**：四状态合法转移、排约/改约/取消/到场登记/完工、费用统计口径。 |
| `src/lib/storage.js` | **存档**：localStorage 读写、版本号与旧数据迁移（v1 的 待处理→待安排，旧数据打开照常使用）。 |
| `src/main.js` | 界面层，只负责渲染与事件，所有变更走状态机返回结果后再落档。 |
| `test/*.test.js` | 三块逻辑的规则测试，`npm test` 运行。 |

数据键沿用 `zfl-14-repairs`，存档结构升级到 `version: 2`；每次事项保留 `appointments` 历史（含已作废的旧码与作废原因），当前有效码只取最后一条未作废预约。
